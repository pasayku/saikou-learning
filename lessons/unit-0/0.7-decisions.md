## Step 4: True or false?

Today, try things at Python's `>>>` prompt. It runs each line as soon as you press **Enter**, which is good for quick tests. Type:

```
python
```

> [!NOTE]
> **The `>>>` prompt is called the REPL**, short for *read, evaluate, print, loop*. It reads a line, works it out, prints the answer, then waits for the next one. You'll see other names for it too. Python's own docs call it *interactive mode*, and *Automate the Boring Stuff* calls it the *interactive shell*. They all mean the same thing.

When you see `>>>`, type each of these and press **Enter**:

```python
75 > 50
75 < 50
50 == 50
50 != 50
```

You get `True`, `False`, `True`, `False`. A comparison asks a question, and Python answers `True` or `False`. These two values are called **booleans**. They start with a capital letter.

| Sign | Means |
| --- | --- |
| `==` | Equal to |
| `!=` | Not equal to |
| `>` | More than |
| `<` | Less than |
| `>=` | More than or equal to |
| `<=` | Less than or equal to |

> [!IMPORTANT]
> **`=` and `==` are different.** One `=` stores a value: `mark = 50`. Programmers call this **assigning** a value to a variable, and `=` is the **assignment operator**. Two, `==`, ask a question: *is* `mark` equal to 50? Mixing them up is one of the most common mistakes in programming.

Try it with a variable, and with text:

```python
mark = 42
mark >= 40
mark == 42
"Maths" == "maths"
```

The last one is `False`. To Python, a capital `M` and a small `m` are different letters.

Type `exit()` and press **Enter** to leave the REPL and go back to Git Bash. You'll see the `$` at the end of the prompt again. Commands like `cd` and `ls` only work at the `$` prompt, not at `>>>`, so always check which one you're at.

## Step 5: `if`

Let's make a fight in a roguelike game. Make a new file:

```
cd work/unit-0
touch fight.py
code fight.py
```

Type this in:

```python
# A fight in a roguelike game
health = 30
damage = 45
health = health - damage
print(f"You take {damage} damage. Health left: {health}")

if health <= 0:
    print("You died. Back to the start of the run.")
print("Thanks for playing.")
```

`health = health - damage` looks odd if you read `=` as "equals". Read it as an assignment: work out `health - damage`, which is `-15`, and assign that to `health`. The old value, `30`, is replaced.

Run it:

```
python fight.py
```

You should see:

```
You take 45 damage. Health left: -15
You died. Back to the start of the run.
Thanks for playing.
```

Here's how `if` works:

- `health <= 0` is the **condition**. It's a comparison, so it's `True` or `False`.
- The line ends with a colon, `:`.
- The lines under it are **indented**: pushed to the right by 4 spaces. They only run when the condition is `True`.
- `print("Thanks for playing.")` isn't indented, so it isn't part of the `if`. It always runs.

Press **Tab** in VS Code to indent a line by 4 spaces.

Now change `damage` to `10` and run it again. Health is `20`, the condition is `False`, and Python skips the indented line. You don't die, and the game still says thanks.

**Break it on purpose.** Delete the 4 spaces before `print("You died...")`, so it lines up with the `if`. Save and run it. The last line of the error says:

```
IndentationError: expected an indented block after 'if' statement on line 7
```

Python needs at least one indented line after an `if`. Put the spaces back. Then delete the `:` at the end of the `if` line and run it again:

```
SyntaxError: expected ':'
```

Put the `:` back and check that it runs.

## Step 6: `else`

`else` gives the program something to do when the condition is `False`. Change the end of `fight.py` to this:

```python
if health <= 0:
    print("You died. Back to the start of the run.")
else:
    print("Still standing. Keep going.")
print("Thanks for playing.")
```

`else` has no condition, because it means *everything else*. It ends with `:`, and the lines under it are indented too.

Run it with a `damage` of `45`, then `10`. Exactly one of the two messages shows each time, never both.

## Step 7: `elif`

What if there are more than two paths? `elif` is short for *else if*. Change the end of the file again:

```python
if health <= 0:
    print("You died. Back to the start of the run.")
elif health < 20:
    print("Low health! Drink a potion.")
else:
    print("Still standing. Keep going.")
print("Thanks for playing.")
```

Python checks each condition from the top down. It runs the block under the **first** one that's `True`, then skips the rest. If none of them are `True`, it runs the `else`. You can have as many `elif`s as you like.

Try `damage` values of `45`, `15` and `5`. You should see a different message each time.

**Order matters.** Swap the first two checks, so `health < 20` comes first:

```python
if health < 20:
    print("Low health! Drink a potion.")
elif health <= 0:
    print("You died. Back to the start of the run.")
```

Run it with a `damage` of `45`. Health is `-15`, and the game tells you to drink a potion. You're dead!

What happened? `-15` *is* less than `20`, so the first condition is `True`. Python runs that block and never gets to the second check. Put the most specific check first, then work outwards. Swap them back before you go on. You'll need this idea in the exercise.

## Step 8: `and` and `or`

Sometimes one decision depends on two things. Add these lines to the bottom of `fight.py`:

```python
level = 5
has_key = True

if level >= 5 and has_key:
    print("The boss door opens.")
else:
    print("The boss door stays shut.")
```

- `and` is `True` only when **both** sides are `True`.
- `or` is `True` when **at least one** side is `True`.

Run it. The door opens. Now change `has_key` to `False` (no quotes, capital F). The door stays shut. Then change `and` to `or` and run it again. Level 5 is enough on its own now, so the door opens.

> [!NOTE]
> **Each side of `and` or `or` needs a whole comparison.** In English you'd say "health is more than 0 and less than 20". In Python, you have to say `health` twice:
>
> ```python
> if health > 0 and health < 20:
> ```
>
> `if health > 0 and < 20:` is a `SyntaxError`.

## If something goes wrong

- **`IndentationError: expected an indented block`:** the line under an `if`, `elif` or `else` needs 4 spaces in front of it.
- **`IndentationError: unexpected indent`:** a line has spaces in front of it, but it isn't under an `if`. Take them out.
- **`SyntaxError: expected ':'`:** an `if`, `elif` or `else` line is missing its `:` at the end.
- **`SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?`:** you used one `=` in a condition. Comparisons need `==`.
- **`TypeError: '>=' not supported between instances of 'str' and 'int'`:** you're comparing text with a number. Check that `int` is around each `input` for a number.
- **Every mark gets the same grade:** check the order of your conditions. Start from A1.
- **Some other error?** Read the last line and the line number, check that line, and send me the whole error if you're still stuck.
