## Step 2: Two shortcuts that save typing

Learn these first. You'll use them all day.

**Tab completes names.** Type the start of a file or folder name, then press **Tab**. The terminal fills in the rest. Try it:

```
ls les
```

Press **Tab** before **Enter**. The terminal finishes it as `ls lessons/`. If nothing happens, more than one name matches. Type another letter and press **Tab** again.

**The Up arrow brings back old commands.** Press **↑** to see the command you ran last. Press it again to go further back. Press **Enter** to run it again, or edit it first.

And when the terminal gets crowded, `clear` empties the screen. Your files are untouched.

## Step 3: Where you are, and how to get elsewhere

Every folder has a **path**, its address on your laptop. Run:

```
pwd
```

You'll see `/c/Users/saku/projects/saikou-learning`. Read it from left to right: drive `C`, then the folders inside each other, down to `saikou-learning`.

You can move around with these:

| Command | Takes you to |
| --- | --- |
| `cd lessons` | The `lessons` folder inside the folder you're in |
| `cd ..` | One folder up. `..` means "the folder above this one." |
| `cd ~` | Your home folder |
| `cd -` | Wherever you were just before |
| `cd ~/projects/saikou-learning` | Your repo, from anywhere |

Try them, and run `pwd` after each one to see where you've landed:

```
cd lessons
cd unit-0
pwd
cd ..
cd ..
pwd
```

You should end up back in `saikou-learning`. You can also go up two folders at once with `cd ../..`.

> [!NOTE]
> **Same files, different view.** The terminal and File Explorer show the same files. Run `explorer .` and File Explorer opens on the folder you're in. File Explorer writes the path as `C:\Users\saku\...`, with backslashes. Git Bash writes it as `/c/Users/saku/...`. They're the same place.

## Step 4: Hidden files

Run:

```
ls -a
```

You'll see something like this:

```
./  ../  .git/  journal.md  lessons/  README.md
```

A `/` at the end of a name means it's a folder. The `-a` means *all*. Now you see things `ls` was hiding: `.` (this folder), `..` (the folder above), and `.git`.

The `.git` folder is where Git keeps every picture you've ever taken of your repo, all your commits. **Never change or delete anything inside `.git`.** Git looks after it for you.

Names starting with a dot are hidden by default. You'll meet more of them later.

## Step 5: Make your work folder

Now for the exercise. Make the folders for this unit's work:

```
mkdir work
cd work
mkdir unit-0
cd unit-0
pwd
```

`pwd` should end in `/saikou-learning/work/unit-0`.

**Use hyphens, not spaces, in names.** A space in a file or folder name makes commands harder to type, because the terminal reads a space as the gap between two things. `unit-0` is easy. `unit 0` causes trouble.

## Step 6: Make, copy, move and delete files

Still in `work/unit-0`, try each of these. Run `ls` after each one to see what changed.

**Make an empty file:**

```
touch practice.txt
```

**Copy it.** `cp` takes the file to copy, then the name of the copy:

```
cp practice.txt copy.txt
```

**Rename it.** `mv` means *move*. Moving a file to a new name in the same folder renames it:

```
mv copy.txt renamed.txt
```

**Move it into a folder:**

```
mkdir old
mv renamed.txt old/
ls old
```

**Delete files:**

```
rm practice.txt
rm old/renamed.txt
```

**Delete an empty folder:**

```
rmdir old
```

`ls` now shows nothing. The folder is empty again.

> [!WARNING]
> **`rm` doesn't use the Recycle Bin.** A file you delete with `rm` is gone. Check the name before you press **Enter**. If a file was committed, Git can bring it back, which is one more reason to commit often.

## Step 7: Write your command notes

Make a file for your own notes on the commands you've learned, and open it in VS Code:

```
touch commands.md
code commands.md
```

Write a short note for each command, **in your own words**. Don't copy from this lesson. Explaining it yourself is how you'll remember it. Use this layout, and add a row for each command:

```markdown
# Command Line Notes

| Command | What it does                           |
| ------- | -------------------------------------- |
| `pwd`   | Shows which folder I'm in, as a path   |
| `ls`    |                                        |
```

Each row is one command. The `|` marks separate the columns, and the `---` line under the first row tells Markdown it's a table. Your columns don't need to line up neatly. The preview (**Ctrl + Shift + V**) lines them up for you.

Include at least: `pwd`, `ls`, `ls -a`, `cd`, `cd ..`, `cd ~`, `mkdir`, `touch`, `cp`, `mv`, `rm`, `rmdir`, `clear`, and the **Tab** and **↑** shortcuts.

Save the file (**Ctrl + S**). Keep it. You can look things up in it later, and add to it as you learn more.

## Step 8: Commit your notes

Go back to the top of your repo, and see what Git notices:

```
cd ../..
git status
```

Git lists `work/` under **Untracked files**. When a whole folder is new, Git shows only the folder's name, not every file inside it.

Put the whole folder on the stage, then take the picture:

```
git add work
git commit -m "Add command line notes"
```

## Step 9: Journal, commit and push

Add today's entry to the bottom of `journal.md`: what you did, and anything that confused you. Save it, then:

```
git add journal.md
git commit -m "Add journal entry for Lesson 0.4"
```

Run `git status`. Git says **Your branch is ahead of 'origin/main' by 2 commits**. You've taken two pictures since your last push, and one push sends both:

```
git push
```

No internet right now? That's fine. Push next time you have internet access.

## If something goes wrong

- **`No such file or directory`:** the name is misspelled, or you're in a different folder than you think. Run `pwd` and `ls` to check. **Tab** helps avoid typos.
- **`rmdir: failed to remove 'old': Directory not empty`:** there's still something inside. Run `ls old` to see what.
- **`explorer .` does nothing:** open File Explorer yourself, and go to `C:\Users\saku\projects\saikou-learning`.
