# Lesson 0.3 questions

Your questions from Lesson 0.3. Asking about the parts that weren't clear is how you learn this stuff.

## 1. What do `pull.rebase` and `core.editor` do?

Both are settings. `git config --global` saves a setting once, and Git uses it in every repo on your laptop from then on. You won't need to type them again.

### `pull.rebase true`

Sometimes you'll commit on your laptop while I add a lesson on GitHub. Then `git pull` has two sets of new commits to combine, yours and mine. With this setting, Git sets your commits aside, brings in mine, and puts yours back on top. Your history stays in one neat line, and Git doesn't stop to ask you what to do.

### `core.editor "code --wait"`

Sometimes Git needs you to type something, like a commit message. It opens an editor for that. The usual one is called Vim, and it's famous for being hard to even close. This setting makes Git open a VS Code tab instead.

## 2. What does `-m` do in `git commit -m`?

You've got the first part right: a commit saves a snapshot of your changes. Remember the "picture" from the lesson.

`-m` stands for **message**, the caption on the picture. It lets you write the message right there in the command:

```
git commit -m "Update journal"
```

If you leave out `-m`, Git still wants a message, so it opens a VS Code tab and waits for you to type one. That's where `core.editor` comes in, so your two questions are connected.

## 3. How do I type `cd` and `code .` as one command?

From your journal. You don't need to! When a lesson shows a box with two lines, like this:

```
cd saikou-learning
code .
```

each line is its own command. Type the first one and press **Enter**. Then type the second one and press **Enter**. The terminal is supposed to run each command as soon as you press Enter, so it was doing the right thing.

If you ever do want both on one line, put `&&` between them:

```
cd saikou-learning && code .
```

`&&` means "run the first command, and if it works, run the second one." You don't need this yet, but you'll see it around.

### Why `cd saikou-learning` gave an error

My guess: the first time you pressed Enter, `cd saikou-learning` worked, and you were inside your repo. When you typed it again, the terminal looked for a `saikou-learning` folder *inside* `saikou-learning`. There isn't one, so you got an error.

`cd` only looks in the folder you're in now. If it says `No such file or directory`, run `pwd` to see where you are. Running `ls` shows which folders you can `cd` into from there.

## 4. Can `git add` add more than one file at once?

Yes. List the files with a space between them:

```
git add journal.md README.md
```

Or add every changed file in the folder you're in:

```
git add .
```

Remember that `.` means "this folder", like in `code .`. It's quick, but it adds *everything* you changed, so run `git status` first to check that's what you want.

## 5. Can I push without `git add` and `git commit`?

No. `git push` only sends **commits** to GitHub. If you changed a file but didn't commit it, Git has nothing new to send, and `git push` says `Everything up-to-date`.

Think of the picture from the lesson again:

1. `git add` chooses what goes in the picture.
2. `git commit` takes the picture and keeps it on your laptop.
3. `git push` sends your pictures to GitHub.

It can feel like a lot of steps, but there's a good reason they're separate. Steps 1 and 2 don't need internet. You can commit many times during a study session, then push them all at once when you have a connection.
